# Federated Learning Checkpoint Analysis & Visualizations Guide

This document explains the tools and scripts implemented to analyze the federated learning checkpoints in this project. The visualizations generated by these tools provide critical insights into client drift, convergence, and heterogeneous learning paths—ideal for inclusion in a technical report.

## 1. Modifications to the Server (`custom_strategy.py`)

By default, Flower aggregates client updates in memory and then discards them to save disk space. To perform per-client analysis (like t-SNE clustering based on client data distributions), we modified `custom_strategy.py` to persist incoming client updates before aggregation.

**Implementation Details:**
In the `aggregate_train` method, we added logic to extract the `arrays` object from each message and save it to the disk under `checkpoints/client_updates/round_{server_round}/client_{partition_id}.pt`. 

*Note: The script `visualize_client_tsne.py` depends on these files being generated by your next training run.*

## 2. Visualization Scripts

All scripts are written in Python and should be executed within your `facerec` conda environment using the local Python binary (`./python <script_name>.py`).

### A. Global Trajectory PCA (`visualize_global.py`)

**What it does:**
This script loads the `global_backbone` models stored by the server for each round. It flattens the parameters of the deepest convolutional layer, applies Principal Component Analysis (PCA) to reduce the dimensionality to 2D, and plots the optimization path from Round 1 to the final round.

**Why include this in the report?**
- **Optimization Path:** Shows whether the global model is traversing smoothly towards a local minimum or if it is oscillating (which might indicate a learning rate that is too high).
- **Convergence Verification:** A path that spirals tightly at the end indicates convergence.

**Output:** `global_trajectory_pca.png`

### B. Client Pseudo-Gradient t-SNE (`visualize_client_tsne.py`)

**What it does:**
It takes the saved client updates for a specific round, computes the "pseudo-gradient" for each client ($g_i = w_{client\_i} - w_{global\_previous}$), and projects these massive gradient vectors into a 2D space using t-SNE.

**Why include this in the report?**
- **Client Heterogeneity (Non-IID Data):** In federated face recognition, clients typically have disjoint identities. This plot will clearly show client updates forming distinct clusters based on their disjoint datasets. 
- **Identifying Stragglers/Outliers:** Helps visually detect if any client is diverging severely from the pack due to bad data or extreme non-IID conditions.

**Output:** `client_tsne_round_X.png`

### C. Global Weight Divergence / Client Drift (`visualize_drift.py`)

**What it does:**
It computes the $L_2$ Euclidean distance between consecutive global checkpoints: $||w^{(t)} - w^{(t-1)}||_2$.

**Why include this in the report?**
- **Client Drift Measurement:** The update magnitude between rounds is a direct proxy for client drift. In a stable training setup, this value should decay over time.
- **Learning Rate Impact:** You will notice sharp drops in the drift precisely when learning rate decay steps occur. Our initial run showed a massive drop from ~16.4 to ~10.0 precisely at Round 10, confirming the LR schedule was effectively applied and stabilized the model.

**Output:** `global_weight_drift.png`

### D. Layer-wise Update Norms (`visualize_layer_updates.py`)

**What it does:**
It compares the model at Round 1 to the final model (e.g., Round 26), calculating the relative parameter change $||w_{end} - w_{start}|| / ||w_{start}||$ for individual layers across the network.

**Why include this in the report?**
- **Understanding Feature Adaptation:** Shows which parts of the backbone are adapting most to the federated dataset. Usually, early convolutional layers (which extract basic edges/textures) change very little, while deeper layers (representing complex facial features) change significantly.
- **Communication Optimization:** By proving that early layers barely change, you can justify freezing them in future runs to drastically reduce communication payloads!

**Output:** `layer_wise_updates.png`

## 3. Recommended Workflow

1. **Include existing plots:** The PCA trajectory (`global_trajectory_pca.png`), drift analysis (`global_weight_drift.png`), and layer update norms (`layer_wise_updates.png`) are already generated for the `faces_emore_C1` run and ready to be dragged into your report.
2. **Launch a new run:** Execute a new benchmark run using your scheduler. The newly modified server strategy will automatically capture client checkpoints into `checkpoints/client_updates/`.
3. **Generate t-SNE:** After a few rounds complete, run `./python visualize_client_tsne.py` to generate the client clustering visualization.
